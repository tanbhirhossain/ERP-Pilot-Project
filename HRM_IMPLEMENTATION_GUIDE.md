# HRM Implementation Guide - ERP Pilot Project

## Overview
Complete CRUD for all HRM modules with SOLID architecture, integrated with CORE AdminLayout & sync panel for ZKTeCo.

## Installation (on server with PHP 8.2+)
```bash
composer install   # pulls jmrashed/zkteco ^1.0
npm install && npm run build
cp .env.example .env  # configure DB
php artisan key:generate
php artisan migrate
php artisan db:seed  # seeds CORE + HRM permissions
php artisan db:seed --class="Modules\HRM\Database\Seeders\HRMPermissionSeeder"
```

## Modules Implemented

### 1. Organization (Single Row)
- Route: `hrm.organizations.index` (GET/POST/PUT `hrm/organization`)
- Model: `Organization` (name, email, phone, address, website)
- UI: Single form page

### 2. Department
- Routes: `hrm.departments.*` (index, create, store, edit, update, destroy)
- Hierarchy: parent_id self-reference
- UI: DataTable + Create/Edit with parent selector

### 3. Designation
- Routes: `hrm.designations.*`
- Relation: belongsTo Department
- Fields: name, code, grade, level

### 4. Biometric Device (ZKTeCo)
- Routes: `hrm.devices.*` + `POST hrm.devices.test`
- Fields: name, ip_address, port, serial_number, device_model, location, status, auto_sync
- Test connection via fsockopen; real sync via jmrashed/zkteco

### 5. Employee (ALL Relations)
- Routes: `hrm.employees.*` (index, create, store, show, edit, update, destroy)
- Core fields: employee_id (auto EMP-0001), user_id, org/dept/desig, names, contacts, employment_type/status, joining_date
- Sub-tables: EmployeeProfile (present/permanent address, emergency), EmployeeSalary, EmployeeEducation, EmployeeExperience, EmployeeSkill, EmployeePolicy (shift_type Fixed/Flexible/Custom, grace times), EmployeeSupervisor
- Auto employee_id generation

### 6. RosterShift
- Routes: `hrm.shifts.*`
- Types: Fixed (start/end), Flexible (punch_in_window), Custom (max 72h), crosses_midnight

### 7. RosterDuty
- Routes: `hrm.duties.*` + `POST hrm.duties.bulk`
- Assigns employee_id + shift_id + roster_date (unique)
- Bulk assign: date range x multiple employees

### 8. AttendanceLog (Raw Sync)
- Routes: `hrm.attendance.logs.*` + `POST hrm.attendance.logs.process`
- Stores raw punches: device_user_id, employee_id, punch_time, device_id, punch_type, is_processed
- Deduplication on punch_time + device_user_id

### 9. AttendancePair (Paired Engine)
- Routes: `hrm.attendance.pairs.*`
- Generated by AttendanceProcessingService
- Open pair detection within 24h (Fixed/Flex) or 72h (Custom)

### 10. AttendanceDaily (Summary)
- Routes: `hrm.attendance.dailies.*`
- One per employee per duty_date (unique)
- Fields: primary_punch_in/out, primary_worked_hours, total_overtime_hours, grand_total_hours, status (Present/Late/Early Out/Absent/etc)

### 11. Attendance Sync Panel
- Route: `hrm.attendance.sync.index` + sync device/all, settings, manual punch
- Automated sync: `php artisan hrm:sync-attendance` every 15min (scheduled in routes/console.php)
- Models: AttendanceSyncSetting (per device), AttendanceSyncLog
- Manual punch for testing (goes to logs → processed)

## 6-Step Attendance Flow (বাংলা স্পেস)
1. **Raw Log**: ZKTeCo → attendance_logs (is_processed=false) via cron/webhook or manual
2. **Policy Resolve**: EmployeePolicy shift_type (Fixed/Flexible/Custom 72h)
3. **Open Pair Check**: If open attendance_pairs (punch_out IS NULL) within 24/72h → close as punch_out else new punch_in
4. **Shift Auto-Detect**: Fixed→ roster duty shift, Flexible→ punch_in_window, Primary vs Overtime check
5. **Pair & Hours**: worked_hours = diff(punch_in, punch_out), mark logs processed
6. **Daily Summary**: Upsert attendance_dailies (primary + overtime + grand_total, Late/Early detection via grace_time)

## Architecture (SOLID)
- **Interfaces** in `Modules/HRM/Interfaces/{*}` (one per aggregate)
- **Repositories** in `Modules/HRM/Repositories/{*}` using `BuildsDatatableQueries` (search/sort/filter, paginate)
- **Services** inject Interfaces (DIP), e.g. `AttendanceProcessingService` depends on Log/Pair/Daily repos
- **Controllers** depend on Services only, thin, Inertia::render('HRM::...') with '::' resolver
- **HRMServiceProvider** binds all interfaces, loads migrations/routes
- **Frontend** uses CORE's AdminLayout + TreeSidebar + DataTable + SearchableSelect + ConfirmDialog via relative import from `modules/CORE/Resources/js/...`

## ZKTeCo Integration
- Package: `jmrashed/zkteco ^1.0` (in composer.json; run `composer install` on server)
- `AttendanceSyncService::fetchFromDevice()` uses `Jmrashed\Zkteco\Lib\ZKTeco` if class exists, else gracefully returns empty (allows manual mode)
- Configure device IP/port in Biometric Devices CRUD, enable auto_sync
- Sync interval configurable per device (default 15m), window hours
